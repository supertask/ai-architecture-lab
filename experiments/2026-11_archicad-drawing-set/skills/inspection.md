# 図面の点検と、直しの指示の作り方

この実験で、AI が描いた8枚を点検し、直しの指示（`prompts/20_`〜`25_`）を作った手順。点検も指示書きも AI（エージェント）が行った。
ここに書いた手順は公開用に一般化したもの。

> 正直に書いておくこと：実験では、描き方（作法）の比較に、実務の図面（人が描いた図）を見本として使った。
> その見本は公開できない。再現する時は、自分の事務所の図面、手元にある実務の図面集、または `rules/` の作図ルールそのものを見本にする。
> 見本を変えると、見つかる問題も直しの指示も変わる。

## 1周の流れ

1. **書き出す**：`python scripts/export_png.py` で8枚を高解像度の PNG（`out/png/hi_<図>.png`）と、各図の文字（`texts_<図>.json`）に。
   - 立面・平面では地中の画層を隠す（スクリプトが自動で切り替える）。断面だけ出す。
   - 貼り合わせのずれを先に確かめる：立面・断面で、GL の太い横線が1本だけか（画素の行を走査して、図の幅いっぱいの濃い行を数える）。
     壊れた画像で点検すると、指摘の半分が無駄になる。
2. **数値で確かめる**（画像を見る前に）：
   - `python scripts/check_levels.py`：全図のレベル表記を集め、モデルの値（階の高さ・最高高さ）と図どうしを照合。書き方の揺れも出る。
   - 寸法：横の寸法の分割の合計＝全長、高さの寸法の分割の合計＝全高。通り芯の外側の端（外壁の外面まで）の寸法が入っているか。
   - 通り芯：名前と間隔が `grid.json` と同じか、全図で同じ本数か。
   - 屋根を突き抜けている物がないか：全要素の最高高さ（`Get3DBoundingBoxes` の zMax）＝図の「最高高さ」か。
     （実験では、高さを直し忘れた間仕切り1枚のせいで、最高高さが 9,950 になった。`prompts/04_` がその直し）
3. **位置で確かめる**（重なり・はみ出し）：
   - 文字・記号の位置は座標で読む（`GetDetailsOfElements` の Text の座標、`API.Get2DBoundingBoxes` で壁・窓・扉の開き・階段の範囲）。
     重なりは矩形どうしの交差で数える。
   - 画像で見る時は、図全体ではなく、気になる所を拡大して撮る（`SetZoom` で範囲を指定して `SaveCurrentWindowAsImage`）。
     全体の画像では、画像認識が小さな文字の重なりを見落とし、ありもしない重なりを指摘する。
   - 画素で確かめる：撮った時の zoom（モデル座標）から画素⇔座標を換算し、線の始点・塗りの切れ目・文字の範囲を行・列の走査で測る。
4. **描き方を比べる**：自分の図と、同じ種類の見本（上の注意）を並べ、図の種類ごと（断面／立面／平面）に違いを書き出す。
   - 1件ごとに「場所（画像のどのあたり）・何が違う・直し方・重大度」。直し方には「2D の注記で直せる」か「モデルで直す」かを必ず書く。
   - 種類ごとに別のサブエージェントに分けると速い（画像を読むだけなので並行でよい。Archicad には触らせない）。
5. **仕分ける**：
   - モデルで直す物（断面に層が出ない、地面が帯に見える、地中が立面に出る、床の高さが違うなど）→ 自分でスクリプトで直す（`scripts/fixA_*`）。
   - 描き方で直す物 → 図ごとの直しの指示にする（下）。
   - 好みの差（どちらでもよい物）→ 直さない。報告に「直さなかった理由」を書く。
6. **直しの指示を書く**：`prompts/20_`〜`25_` と同じ形で、図ごとに1ファイル。
   - 先頭：どの窓を開くか（`ChangeWindow`）、使う物（tapir_http.py・ルールファイル・grid.json・Archicad から読める情報だけ）、
     高さの基準（GL＝z=0、1FL＝GL+100、値はモデルから読む）、「正しい物は残す」「モデルは変えない」「`GetElementsInDrawOrder` は使わない」。
   - 「直すこと（重要な順）」：具体的に。場所・今どうなっているか・どう直すか・数値（例：「図名を 0.3 m 下げる」）。
   - 毎回入れる3行：
     - 「直した所の半径 1 m の文字・線を読み直して、新しい重なりを作らない」
     - 「モデルが原因で 2D では直せない物（梁の白抜け・基礎のすき間・壁の二重など）は直さず『モデル側：…』と報告」
     - 「済んだ項目は確かめるだけで飛ばす」（時間切れでやり直す時に効く）
   - 部品が自分で出す文字（はめ殺しの「FIX」など）は「そのまま。手で足さない」と書く。
   - 防水の線など「どこに引くか」を間違えやすい物は、対象の面（どのスラブの上面か）を列挙する。
7. **流す**：`SHEETS='20_fix_SA_round2 ...' AGENT_CMD='...' bash scripts/run_sheets.sh`（1枚ずつ、保存付き）。直しは1枚の上限を長めに（45 分）。
8. **同じ失敗を繰り返さないよう、作図ルールに足す**：見つかった失敗を、そのルールファイルの「前回の失敗」の節
   （`rules/作図ルール_断面.md` の「前回の失敗」、`rules/作図ルール_立面.md` の「11/16 の点検で足した決まり」のような節）に、
   「何をした → 正しくは」の1行で足す。次に1枚目から描かせる時、1回で仕上がる割合が上がる。
9. **AI の直しの後に自分で見る**：書き出し直して、新しい重なり・部屋の外に出た文字・悪化した所がないか。
   指示が悪くて図が悪くなった時は、AI が作った要素を消して戻し、指示を直す。

## いつ止めるか
- 2周目からは、点検に「前の周の指摘：直った／直っていない／一部」の表と、最後に
  「実務の図として問題なし（残りは好みの差）／直すべき問題あり」の判定を書かせる。止める根拠はこの判定。
- 2〜3周で、残りが軽い物だけになったら止める。回すたびに新しい小さなずれが出るので、無限に回さない。
  問題の無い図は回さない。
- 実験では、断面・立面は3回、平面は2回直した（TECHNICAL.md の「直しの回数」）。

## 画像認識（vision）の使い方
- 値の正誤（数字）を画像認識で判断しない。6,950 を 6,900、700 を 750 と読み違える。数字は文字データ（texts_*.json）とモデルで照合する。
- 位置の判断も画像認識だけにしない。重なりの誤報が多い。座標と画素で確かめてから指摘にする。
- 画像認識に聞くのは「全体が写っているか」「この種類の図として何が足りないか」など、大づかみの質問に向いている。
