# skills：AI エージェントに渡す「描き方」と「操作のコツ」

このキットの知識は3つに分かれている。どれも Markdown なので、どの AI エージェントにもそのまま読ませられる。

| 中身 | ファイル | いつ読ませるか |
| --- | --- | --- |
| 作図ルール（描き方） | `../rules/作図ルール_平面.md`・`作図ルール_断面.md`・`作図ルール_立面.md` | 図を描く回。指示（`prompts/10_`〜`17_`, `20_`〜`25_`）が、描く図の種類のルールを1つだけ指定している |
| Archicad 操作のコツ | `archicad-operation.md` | Archicad を API で動かす回すべて。指示を自分で書く時の注意も入っている |
| 点検と直しの指示の作り方 | `inspection.md` | 描き上がった図を点検し、直しの指示を書く人（または AI）が読む |

- 作図ルールは `rules/` に置いたまま（指示文がそのパスを読むため。`scripts/prepare_workdir.py` が作業フォルダにコピーする）。
- 作図ルールは、実務の図面の描き方（作法）を整理したもの。形・間取り・数値は写していない。
- 実験の描く回では、エージェントに「この指示とルールファイルと Archicad から読める情報だけを使う」と縛った
  （スキル・記憶・過去の会話を使わせない）。`archicad-operation.md` の中身のうち、描く回に要る物は指示文に直接書いてある
  （`GetElementsInDrawOrder` を使わない、など）。同じ条件で再現するなら、描く回には `archicad-operation.md` を渡さなくてよい。

## エージェントへの渡し方

- **1回だけ読ませる**：指示の中で「`<WORK>/skills/archicad-operation.md` を先に読んで」と書く、または会話の最初に
  「このファイルを読んでから作業して」と入力する（`<WORK>` は作業フォルダ）。
- **毎回読ませる**：エージェントごとの「常に読む説明ファイル」に、このファイルへのリンクか中身を入れる。
  - Claude Code：作業フォルダの `CLAUDE.md`、または `.claude/skills/<名前>/SKILL.md`（先頭に name と description を書く形式）
  - Codex：作業フォルダの `AGENTS.md`
  - Hermes：スキル（`SKILL.md` の形式）として登録する
  形式は各エージェントの説明書で確かめる。どれも Markdown を読むだけなので、中身はこのファイルのままでよい。
- **文脈を増やしすぎない**：全部のルールを一度に読ませない。描く図の種類のルールだけを渡す。関係のある文脈が多すぎると、規則を守る率が下がる。
