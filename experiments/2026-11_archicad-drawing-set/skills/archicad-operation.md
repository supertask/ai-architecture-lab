# Archicad を AI エージェントで動かす時の操作のコツ（Tapir / JSON API）

この実験とその前の実験で、実際に詰まった所と、効いた対策だけを書いた。特定の事務所・案件の決まりは入れていない。
「版によっては」と書いた所は、Archicad や Tapir の版で振る舞いが変わる可能性がある所（確かめた版以外では未確認）。

## つなぎ方
- Archicad の JSON API（`http://127.0.0.1:19723`）に、Tapir アドオンの命令を `API.ExecuteAddOnCommand` で包んで送る。
  `scripts/tapir_http.py` の `call(port, 'CommandName', params)` が Tapir、`api(port, 'API.X', params)` が Archicad 本体の命令。
- MCP は要らない。Python を書いて実行できるエージェント（Claude Code、Codex、Hermes など）ならそのまま使える。
- 最初に `scripts/check_connection.py` で、Archicad・Tapir・階が読めるかを確かめる。
- 命令の引数が分からない時は、Tapir の命令一覧（Tapir の公開リポジトリの説明）で名前と引数を確かめてから書く。
  当て推量で何度も送らない。

## 落とさない・失わない
- **1枚（1手順）ごとに保存する**：`SaveProject {}`。返事ではなく、.pln の更新時刻で保存できたかを確かめる。
  8枚を続けて描かせた時、エージェントは自分では保存せず、途中で Archicad が落ちた。保存はスクリプト側（外）から送る（`scripts/run_sheets.sh`）。
- **長い作業は 1枚 = 1回の実行に分ける**。続けて動かすほど落ちやすく、落ちた時に失う量も増える。
- **命令を同時に送らない**。Archicad に命令するエージェント・スクリプトは常に1つだけ。前の実行が終わってから次を始める
  （画像を見るだけの点検は並行でよい）。命令の実行中に Archicad の画面を触らない（Esc やメニュー操作で固まったことがある）。
- **`GetElementsInDrawOrder` を使わない**。これを呼んだ直後に Archicad が落ちたことがある（原因は確定していないが、使わない指示にしてから再発していない）。
  重い読み取り（全要素の詳細など）は1回ずつ分けて送る。
- 落ちた後は、最後に保存した .pln を開いて、終わっていない手順だけをやり直す。起動時の「プロジェクトの復元」は、
  復元データの方が新しく、かつ中途半端な状態でない時だけ使い、開いたらすぐ保存する。
- 作り直し・まとめて消す・ビューを作り直すなど重い操作の前にも保存する。

## 窓（ビュー）とデータベース
- `GetElementsByType` などは「今開いている窓のデータベース」を読む。3D の窓のままだと壁が 0 本で返る。
  0 本と出たら「無い」と決めずに、`ChangeWindow {windowType: 'FloorPlan', storyIndex: 0}` に切り替えてから読み直す。
- 断面・立面の窓は、表示名（「S-01 A-A」）ではなく `GetDatabases` の `name`（「A-A」）で探して、その `databaseId` で `ChangeWindow` する。
  参照ID を変えると表示名が変わるため。
- **版によっては、作ったばかりの断面の窓を API で開けない**（"Failed to change current database"）。
  ナビゲータ › プロジェクト一覧 › 断面図 で一度ダブルクリックして開くと、以後は API で切り替えられる。
- **断面記号の参照ID（既定は全部「S-01」）を A / B に変えるのは GUI だけ**：ナビゲータで断面図を右クリック →
  「断面図の名前を変更...」。変えないと平面図に出る記号が全部 S-01 になる。このキットでは、8枚を描いた後に人が変える（README の表の段 8。実験では直しの3回目と4回目の間に変えた）。変えた後は、窓の表示名「S-01 …」で探す指示（`20_`・`21_` など）は窓が見つからないので、name で探して databaseId で開く（`22_`・`25_` の書き方）。
- 断面マーカーはナビゲータからは消せないことがある。`CutPlane` 要素として `GetElementsByType` → `DeleteElements` で消す。
- `SetZoom` の直後の1回目の `SaveCurrentWindowAsImage` は、前の表示が写ったり白紙になったりする。3 秒ほど待って2回撮り、2枚目を使う。
  画像の大きさは窓の大きさで決まるので、高解像度が要る時は範囲を分けて撮って貼る（`scripts/export_png.py`）。保存先は絶対パスで。

## モデルの直し
- 断面に層を出すには、壁・スラブを複合構造にする（`CreateComposites` → `ModifyWalls` / `ModifySlabs` の `compositeId`）。
  作図ルールでは層を足せない。厚さの合計を今の厚さと同じにすると、面・通り芯・寸法が動かない。
- 外壁の室内側の判定：`flipped=True` の壁では複合構造の最初の層が進行方向の右に来る。壁の中点から左右 0.3 m の点が
  どの部屋（ゾーン）に入るかで室内側を決め、向きの逆の複合構造を使い分ける（`scripts/fixA_walls.py`）。
- 家ごと上げる（1FL=GL+α）：`SetStories` に全部の階の項目（index, floorId, dispOnSections, level, height, name）を渡す。
  要素は階と一緒に動く。地面・水盤の板は `ModifySlabs zCoordinate` で元に戻す（`scripts/fixA_raise.py`）。一部の項目だけ渡すと失敗した。
- `CreateSlabs` の `level` は絶対高さ（階からの相対ではない）。壁の `zCoordinate` は階からの相対。
- `SetDetailsOfElements` で高さや下端を変えようとしても、受け付けて何も変わらない項目がある。返事の成功ではなく、
  `Get3DBoundingBoxes` の z を読み直して確かめる。
- まとめて変える時は、厚さだけで選ばない（薄いガラス壁や立上りも同じ厚さで引っかかる）。厚さ＋高さなど2つ以上の条件で選び、変えた一覧を出す。

## 書き出し
- **立面・平面を書き出す時は、地中（基礎・床の層・敷地の板）の画層を隠す**。立面・平面に GL より下の線や敷地の板の輪郭が出る。
  2D の白い塗りでは隠せない（断面・立面の窓では 2D の塗りがモデルの線の下に描かれる）。断面だけ表示する（`scripts/layer_found.py hide|show`）。
- 敷地の板の上端を GL にし、1階の外壁の下端を GL まで下げると、地中を隠した時に壁と地面の間にすき間が出ない。
- 部屋（ゾーン）は断面・立面の窓に箱として線が出ることがある。気になる時はゾーンの画層を書き出しの時だけ隠す。

## エージェントへの指示の書き方
- 指示には「使ってよいのはこの指示・ルールファイル・Archicad から読める情報だけ」と書く。前の図や記憶の値を使うと、図ごとに高さや通り芯がずれる。
- **通り芯は最初に1組だけ決めてファイル（grid.json）に書かせ、全部の図でそれを使わせる**。図ごとに決めさせると、本数も間隔もばらばらになる。
- レベルの書き方（▽最高高さ・▽軒高・▽2FL・▽1FL・△GL など）、断面名（A-A・B-B）は、全部の指示で同じ言葉を使う。
- 「切断面の上に塗りを重ねない」と書く。重ねると、モデルの層が隠れる。
- 狭い部屋（WC・収納・浴室など）に面積・帖を足させない。部屋に入らず、引出線で外に出して読み違える図になった。
- 部品が自分で出す文字（はめ殺しの「FIX」など）は、手で足させない（二重になる）。
- 「送る前に、何を描くかを日本語1行で書く」「直したら座標を読み直して重なりを数値で確かめる」を入れると、途中経過が追える。
- 1枚の上限時間は長めに（直しの回で 45 分）。止まった図は「まず今の状態を読み、済んだ項目は飛ばす」を先頭に足してやり直す。
- 指示ファイルや指示文にパスを書く時はスラッシュ（`C:/...`）で書く。Python の文字列でバックスラッシュのパスを書き出すと `\r` `\a` が制御文字に化ける。

## 確かめ方
- 見た目の判断を画像認識（vision）だけに任せない。数字の読み違い（6,950 → 6,900 など）や、ありもしない重なりの指摘がよく出る。
  値は API で読み、位置は画素の走査や座標で確かめる（`skills/inspection.md`）。
- AI の完了報告の数値（「すき間 0.1 m あけた」など）だけで合格にしない。書き出した図を見て確かめる。
