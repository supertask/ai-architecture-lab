# AI_GUIDE：この実験を再現する AI エージェントへの手順書

あなた（AI エージェント）は、このフォルダ（以下 `<KIT>`）を使って、建築家のユーザーと一緒に
「白紙の Archicad に家を組み、作図ルールに沿って図面8枚を描き、点検して直す」を再現します。
ユーザー向けの説明は [README.md](README.md)、ファイルの一覧と実験の細部は [TECHNICAL.md](TECHNICAL.md) にあります。

ユーザーは次の3つの言葉で頼んできます。それぞれ下の「段階1〜3」に当たります。

| ユーザーの言葉 | 段階 |
| --- | --- |
| 「このフォルダの AI_GUIDE.md を読んで、白紙の Archicad に家を組んで」 | 段階0（準備の確認）→ 段階1（家を組む） |
| 「作図ルールに沿って、平面図・立面図・断面図の8枚を描いて」 | 段階2（8枚を描く） |
| 「描いた図を点検して、直して」 | 段階3（点検と直し） |

言葉が少し違っても、意味が合えばその段階を進めてください。前の段階が終わっていなければ、そのことを伝えてから前の段階を先に行います。

## ユーザーとの約束（必ず守る）

1. **ユーザーは建築家で、プログラマーではない。** コマンド、ファイルのパス、プログラム用語（JSON、API、Python、ポート、スクリプトなど）を、ユーザーへの返事に出さない。どうしても要る時は、ひとことで言い換える（例：「Archicad と AI がつながっているかの確認」）。
2. **コマンドは全部あなたが実行する。** ユーザーに「これを実行して」と頼まない。Python の用意、作業フォルダ作り、保存も自分で行う。
3. **進み具合を、建築の言葉で短く伝える。** 区切りごとに1〜3行。例：「1階の壁を置き終わりました。次は2階の壁です」「3枚目（A-A 断面図）が描けました。残り5枚、目安はあと2時間ほどです」。
4. **画面の操作が要る時だけ、ユーザーに頼む。** 1回に1つ、メニューの場所まで具体的に書き、「終わったら『できた』と送ってください」と添えて、返事を待つ。
5. **Archicad への命令は、いつも1本ずつ。** 2つのスクリプトやエージェントから同時に送らない。命令を送っている間は、ユーザーに Archicad の画面を触らないよう頼む。
6. **1つの指示（1枚の図）が終わるたびに保存する**：`python scripts/check_connection.py --save`。
7. **結果を作らない。** 失敗した時は、何が起きたかを平易に伝え、次の手を提案する。描けていない図を「描けた」と言わない。
8. **触ってよいのは、`<KIT>` の中と、このために開いた Archicad のプロジェクトだけ。** ほかのファイルや、ほかの Archicad のプロジェクトは開かない・変えない（`make_sections.py create` はプロジェクトの断面マーカーを全部消すので、特に注意）。
9. アプリが「コマンドを実行してよいか」を聞いてくる時は、「作業のために、このフォルダの中でプログラムを動かす許可です」と説明してよい。

## 段階0：準備の確認（最初に1回）

1. **Python があるか**：`python --version`（無ければ `python3`、`py -3` を試す。`uv` があれば `uv run python` でもよい）。
   - 無い時は、ユーザーに「作業に使う Python という道具が入っていません。入れてよいですか」と聞き、許可を得てから入れる。
   - 画像の書き出しに Pillow と numpy を使う（`pip install pillow numpy`、または `uv run --with pillow --with numpy python ...`）。
2. **Archicad とつながるか**：`python scripts/check_connection.py`
   - `OK: Archicad JSON API` と `OK: Tapir アドオン` が出れば進む。
   - 「ポート 19723 に Archicad が見つからない」：
     - Archicad が起動していて、プロジェクトが開いているかをユーザーに確かめてもらう。
     - Archicad を2つ以上開いていると番号がずれることがある。`ARCHICAD_PORT` を 19724〜19744 に変えて試す。
     - それでもだめなら、ユーザーにこう伝えて止まる：「Archicad と AI をつなぐ最初の準備が、まだ済んでいないようです。セットアップ資料 https://claude.ai/artifact/UwQrsxsWJztdwNVAd93t8T のプロンプトをこのアプリに貼って、準備を済ませてから、もう一度頼んでください。」
   - 「Tapir の命令が通らない」：ユーザーにこう伝えて止まる：「Archicad に、AI から動かすための追加機能（Tapir）が入っていないようです。セットアップ資料 https://claude.ai/artifact/UwQrsxsWJztdwNVAd93t8T の手順で入れて、Archicad を開き直してください。」
3. **白紙のプロジェクトか**：`check_connection.py` が表示する階と、要素の数（`GetAllElements` など）を確かめる。壁などが既にあれば、ユーザーに「今開いているプロジェクトに、すでに壁などがあります。新しい空のプロジェクトを開いてください（ファイル › 新規）」と頼む。
4. **bash があるか**（`bash --version`）。あれば `scripts/run_sheets.sh` を使える。無ければ下の「指示の流し方」の方法Bで進める。

## 指示の流し方（段階1〜3で共通）

実験では、`prompts/` の指示1本を、まっさらな会話1つで流しました（前の図の値を使い回さないため）。次のどちらかで流します。

- **方法A（使えるならこちら）**：非対話で1回だけ実行して終わるエージェントのコマンドがある時。
  - 例：`claude -p --dangerously-skip-permissions`（Claude Code）、`codex exec --full-auto`（Codex）。書き方は各エージェントの説明書で確かめる。
  - `SHEETS='01_model_M' AGENT_CMD='…' bash scripts/run_sheets.sh` のように1本ずつ流す。`run_sheets.sh` は1本ごとに保存し、保存に失敗したら止まる。記録は `work/logs/`。
  - 1本の上限は `MAX_SEC`（既定 45分）。
- **方法B**：方法Aが使えない時は、あなた自身が `work/prompts/<名前>.md` を読み、その指示を**その回の唯一の作業内容**として実行する。
  - 指示に「使ってよいのは、この指示・ルールファイル・Archicad から読める情報だけ」とあれば守る（このガイドの内容は、進め方の決まりとしてだけ使う）。
  - 指示の中の「session_search、honcho、delegate は使わない」は実験で使ったエージェントの機能名。「記憶や過去の会話を使わない」と読み替える。
  - 1本終わるごとに `python scripts/check_connection.py --save`。会話が長くなったら、ユーザーに「ここで新しい会話にすると安定します。新しい会話で『AI_GUIDE.md を読んで、続きをやって』と送ってください」と勧めてよい。

どちらでも、進み具合は `work/progress.md` に1行ずつ書き残す（どの指示が終わったか、保存したか）。続きを頼まれた時はこれを読んで再開する。

## 段階1：家を組む（「白紙の Archicad に家を組んで」）

1. 段階0を済ませる。
2. **作業フォルダを作る**：`python scripts/prepare_workdir.py` → `<KIT>/work/` に、指示が読むファイル（`tapir_http.py`・作図ルール・家のスクリプト・画像・skills）と、`<KIT>` を実際の場所に置き換えた指示（`work/prompts/`）ができる。
3. **階を設定して保存**：`python scripts/setup_stories.py <KIT>/work/house_from_scratch.pln`（1FL・2FL・RFL の3つにして、その名前で保存。最初に1回だけ。名前の付いたプロジェクトでは「別名で保存」になる）。
4. **家の外形を組む**：指示 `01_model_M` を流す → 保存。ユーザーに「外壁・床・屋根・窓・扉を置きました」と伝える（約14分）。
5. **間取りと通り芯**：指示 `02_interior_I` を流す → 保存。`work/grid.json`（通り芯）ができたか確かめる（約18分）。
   できていなければ、もう一度 `02_` を流すか、実験の記録を使う（`python scripts/prepare_workdir.py --with-grid`）。使った時はユーザーに伝える。
6. **立面・断面の線を作る**：`python scripts/make_sections.py create`
7. **ここで止まって、ユーザーに頼む（画面の操作1）**：
   > Archicad で、画面の左の「ナビゲータ」の「プロジェクト一覧」にある「断面図」を開いてください。中に6つ（S南・S東・S北・S西・A-A・B-B）あります。それぞれを1回ずつダブルクリックして開いてください（開くだけで、何もしなくて大丈夫です）。終わったら「できた」と送ってください。

   理由：版によっては、作ったばかりの断面の窓を、AI からは開けない。人が1回開くと、以後は AI から切り替えられる。
8. 「できた」を受けたら保存し、`python scripts/make_sections.py shoot` で6面が画像になるかを確かめる（`out/sections/`）。空の画像があれば、その窓の名前を挙げて、もう一度開いてもらう。
9. **モデルを直す（断面に層・基礎・天井を出す）**。順に1本ずつ。区切りごとに保存してよい。`scripts/` で実行：
   ```
   python fixA_snapshot.py      # 直す前の壁の控え
   python fixA_comps.py         # 複合構造（層）を作る
   python fixA_walls.py         # 壁を層付きに（室内側を部屋で判定）
   python fixA_slabs.py         # 計画を表示 → あなたが確かめてから
   python fixA_slabs.py --apply # 屋根・床を層付きに、塊の屋根を板＋天井＋縁の壁に
   python fixA_found.py         # 1階の床（部屋ごと）と基礎
   python fixA_raise.py         # 家ごと +0.1（1FL＝GL+100）
   python layer_found.py        # 地中を専用の画層へ、1階の外壁を GL まで下げる
   ```
   - `fixA_slabs.py` の計画は、振り分けの規則（スクリプトの先頭の説明）に合っているかを見てから `--apply`。実験のモデルでは 0 が3枚、1 が2枚、1a が1枚、2 が3枚、3 が2枚、4 が1枚。大きく違えば、ユーザーに「屋根と床の直し方が、実験の家と少し違う形になりそうです」と伝え、内容を平易に説明してから進める。
   - この前に図を描いていた時だけ、`python fixA_del2d.py --apply`（古い 2D を消す）。
   - 中身の詳細は [TECHNICAL.md](TECHNICAL.md) の「モデルの直し」。
10. 保存して、`python scripts/make_sections.py shoot` で A-A 断面に層と基礎が出たかを画像で確かめる。
11. ユーザーに報告して止まる：何ができたか（3行以内）、次に頼む言葉「作図ルールに沿って、平面図・立面図・断面図の8枚を描いて」。

## 段階2：8枚を描く（「作図ルールに沿って、8枚を描いて」）

1. `check_connection.py` でつながりを確かめる。`work/prompts/` と `work/grid.json` があるか確かめる（無ければ段階1へ）。
2. **窓の名前を確かめる**：指示は断面・立面の窓を「S-01 A-A」「S-01 S南」のような表示名（参照ID ＋ 名前）で探す。`GetDatabases` などで実際の表示名を読み、違えば `work/prompts/` の該当する指示の窓の名前を実際の名前に書き換える（ユーザーが先に参照ID を変えていた時など）。
3. 指示 `10_sheet_P1` 〜 `17_sheet_EW` を1本ずつ流す。1本ごとに保存。1枚終わるごとにユーザーに知らせる：
   - 順番と図の名前：P1＝1階平面図、P2＝2階平面図、SA＝A-A 断面図、SB＝B-B 断面図、ES/EN/EE/EW＝南/北/東/西立面図
   - 目安：断面 30〜35分、立面 14〜19分、平面 12〜26分。8枚で約2時間50分。
   - 方法Aなら `SHEETS` を省くと8枚を順に流せる（`AGENT_CMD='…' bash scripts/run_sheets.sh`）。その場合も1枚ごとに `work/logs/` を見て、ユーザーに知らせる。
4. **Archicad が落ちた時**（保存に失敗した・つながらない）：
   > Archicad が止まったようです。Archicad を開き直して、作業フォルダの中の「house_from_scratch」というファイルを開いてください（復元するか聞かれたら「いいえ」で、保存した所から始めます）。開いたら「できた」と送ってください。

   開いたら、終わっていない図だけを流し直す。
5. **8枚が終わったら、ユーザーに頼む（画面の操作2）**：
   > 平面図に出る断面記号の名前を A・B にします。Archicad のナビゲータの「プロジェクト一覧」→「断面図」で、「A-A」を右クリック →「断面図の名前を変更...」を選び、参照ID を「A」にしてください。「B-B」も同じように「B」にしてください。終わったら「できた」と送ってください。

   （参照ID は AI からは変えられない。変えると窓の表示名も変わるので、これ以降の指示では新しい名前を使う。）
6. 保存し、`python scripts/export_png.py` で8枚を画像にする（`out/png/hi_<図>.png`。立面・平面では地中の画層を自動で隠す）。
7. ユーザーに報告して止まる：8枚が描けたこと、画像の置き場所（「このフォルダの out の中の png フォルダ」）、目についた所（あれば）、次に頼む言葉「描いた図を点検して、直して」。

## 段階3：点検と直し（「描いた図を点検して、直して」）

手順の本体は [skills/inspection.md](skills/inspection.md)。先に読む。要点：

1. **書き出す**：`python scripts/export_png.py`。貼り合わせのずれ（GL の線が1本か）を先に確かめる。
2. **数値で確かめる**：`python scripts/check_levels.py`（レベル表記の照合）、寸法の合計、通り芯（`grid.json`）。
3. **位置で確かめる**：重なりは座標と画素で確かめる。画像を見て「重なっていない？」と判断するだけにしない。数字は画像認識で読まない。
4. **見本と比べる**：見本は `rules/` の作図ルール。ユーザーが自分の事務所の図面を見本として渡したら、それを使う（形や間取りは写さず、描き方だけを比べる）。
5. **ユーザーの指摘を足す**：ユーザーがふつうの言葉で言った直し（「防水の線が笠木の上まで出ている」など）を、場所・今の状態・直し方に言い換えて、直しの指示に入れる。
6. **仕分ける**：
   - モデルが原因の物（層が出ない・基礎のすき間・壁の二重など）は、2D の注記では直さない。ユーザーに「これはモデル側の問題です」と説明し、直すかを聞く。
   - 好みの差は直さず、理由を報告する。
7. **直しの指示を書く**：`prompts/20_`〜`25_` と同じ形で、図ごとに1ファイル。`work/prompts/30_fix_<図>_r<周>.md` のような名前で置く（`<KIT>` の部分は作業フォルダの実際の場所で書く）。毎回入れる3行（skills/inspection.md の6）を忘れない。
8. **流す**：方法Aなら `SHEETS='30_fix_SA_r1 ...' AGENT_CMD='…' bash scripts/run_sheets.sh`。方法Bなら1本ずつ。1本ごとに保存。
9. **作図ルールを育てる**：見つかった失敗を「何をした → 正しくは」の1行にして、`rules/` の該当するファイルの「前回の失敗」の節に足す（立面は「11/16 の点検で足した決まり」の節）。`work/` の同じ名前のファイルにもコピーする。足した行をユーザーに見せる。
10. **書き出し直して、自分で見る**：新しい重なりや悪化が無いか。悪くなった時は、その回で AI が作った要素を消して戻し、指示を直す。
11. **1周ごとに止まって報告する**：
    - 直った所／残っている所（重大な物と好みの差に分けて）
    - 「もう1周直しますか。気になる所があれば、そのまま言ってください」
    - 2〜3周で、残りが軽い物だけになったら終わりを勧める（回すたびに新しい小さなずれが出るため）。

## 再開するとき

ユーザーが「続きをやって」と言ったら、`work/progress.md` と `work/logs/` を読み、`check_connection.py` でつながりを確かめてから、終わっていない所から始める。どこから再開するかを1行で伝える。
